# Houdini backend

Status: **contract only (Milestone 1)**. Generation starts in Milestone 3.

## Role

The Houdini backend consumes IR and emits executable `hou` Python that
rebuilds a native, editable SOP network.

```
IR graph → HoudiniBackend.generate() → houdini_output.py
```

`import hou` is allowed only inside `nodebridge.backends.houdini`, and
only when a script runs *inside* Houdini. The generator itself should
emit text, not import `hou` at NodeBridge install time.

## Planned first path

Geometry Nodes IR → SOP network inside a NodeBridge subnet.

Where a single SOP is insufficient, emit:

* multiple SOP nodes
* an Attribute Wrangle
* generated VEX
* parameter wiring

That is a `GraphFragment`, not a one-to-one rename.

## Conceptual example

```
Blender Set Position
    ↓
IR geometry.modify_position
    ↓
Houdini Attribute Wrangle / equivalent SOP
```

Generated scripts should:

* create a dedicated NodeBridge subnet
* position nodes
* name them clearly
* store source metadata
* expose equivalent parameters
* include a `# Generated by NodeBridge` header

## Capabilities

Houdini advertises `SOP` and `VEX` today. Additional contexts (VOP, LOPs)
can be added later without changing the IR.
